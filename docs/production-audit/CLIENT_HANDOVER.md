# Client handover

Before launch, the company must identify account owners and alternates for its domain and DNS, existing Websouls email service, GitHub, Vercel, Neon and private Blob storage. Use individual administrator accounts, MFA where available and a secure credential handover mechanism. Never send passwords or service tokens in ordinary email or commit them to Git.

The company must approve the contact information and WhatsApp number, catalogue descriptions, product images and usage rights, service area, public claims, privacy notice, terms and any sales, delivery, warranty or return policies that actually apply. See `CLIENT-CONTENT-TO-COMPLETE.md` in the repository root and `REMAINING_ACTIONS.md` in this folder.

Train designated staff to sign in, review and respond to enquiries, download private attachments, edit products/categories, understand publishing statuses and check changes on staging. There is no working email-notification or self-service password-reset delivery workflow in this audit; agree on how staff will monitor enquiries and how the account owner will recover access. Verify the actual procedures in a safe test environment.

Document the support contact, maintenance responsibility, service billing owner, backup schedule, restoration exercise, incident escalation path, domain renewal, permissions review, updates and rollback. The user must approve production deployment, database migration and DNS changes separately.
